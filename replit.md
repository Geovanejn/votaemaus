# Site UMP Emaús

## Overview
This project is a comprehensive web system for the União de Mocidade Presbiteriana (UMP) of the Emaús Presbyterian Church. It aims to enhance community engagement, streamline event management, and provide spiritual resources through a public website, a members-only area, and an administrative panel. Key capabilities include daily devotionals, event scheduling, member management, social media integration, and the interactive DeoGlory study system. The DeoGlory system offers gamified learning, achievement tracking, and real-time progress. The system also includes a Treasury Module for financial management, member fee tracking, and an e-commerce shop with payment integration.

## System Architecture

### UI/UX Decisions
The front-end is built with React and features a responsive design. The DeoGlory study system incorporates gamified elements like ranking, animated feedback, and golden styling for completed sections. Consistent card layouts and color schemes are used. Accessibility features include text-to-speech normalization.

### Technical Implementations
- **Frontend**: React
- **Backend**: Express.js
- **Database**: PostgreSQL (managed with Drizzle ORM)
- **Authentication**: JWT for API security (96h token expiration for 4-day session persistence across server restarts).
- **Scheduled Tasks**: Background tasks for Instagram synchronization, event deadline notifications, devotional comment notifications, daily missions, and abandoned cart reminders.
- **Real-time Features**: Push notifications and WebSocket-based online status.
- **Notification System**: Comprehensive system for push, in-app, and email notifications for various events (devotionals, events, prayer requests, lessons, achievements, birthdays, etc.). Notifications include a standard icon payload. **Browser Compatibility** (Jan 2026): Push notification subscription includes browser detection (Brave, Chrome, Firefox, Safari, Edge, iOS) with browser-specific error messages and setup instructions. Brave users see instructions to enable "Use Google services for push messaging" in brave://settings/privacy. **Auto-Sync Push Subscriptions** (Jan 2026): Push subscriptions are automatically synced every 1 hour (reduced from 6h for reliability) when: user accesses the system (app load), when tab visibility changes (user returns to tab), on login, and when service worker updates. `ensurePushSubscriptionSynced()` function in auth.tsx handles both anonymous subscription linking (via `x-anonymous-subscription-id` header) and browser subscription sync. `/api/notifications/status` endpoint verifies subscription status. Anonymous subscriptions are linked to user accounts after login.
- **AI Integration**: Used for generating exercises and questions from topics or PDFs, with quota tracking and cooldowns. Prioritizes `gemini-3-flash-preview`, `gemini-2.5-flash`, and `gemini-2.5-lite` models. Includes server-side validation for AI-generated questions.
- **Study System (DeoGlory)**: Features an XP system with daily missions, general/annual/seasonal ranking, a crystal reward system, and automatic achievements. Supports multiple-choice, true/false, and fill-in-the-blank quiz mechanics.
- **Devotional Mobile Crop**: Admin tool to define mobile-optimized crop areas for devotional cover images.
- **Admin Panel**: Provides management for users, events, devotionals, directory, marketing (Instagram integration), and the DeoGlory study system (lesson management, AI generation from PDFs). Supports multi-panel access.
- **Special Events System**: Events can include AI-generated lessons, collectible cards with rarity levels, image uploads, and countdown timers.
- **Treasury Module**: Manages member fees (Percapta, UMP), an e-commerce store, and event fee collection. Features financial dashboards and Mercado Pago PIX integration. Includes role-based access for Treasurer and Marketing (Marketing cannot see financial amounts). Excel report generation supports filtering by category (loja, emprestimo). Member financial panel at `/membro/financeiro` shows fee status and payment history. UMP payments follow the "Day 10 Rule": members active on days 1-10 pay from that month, days 11-31 pay from next month. Multi-month UMP payments are tracked via `referenceMonths` JSON field in treasury_entries. Abandoned cart sends 4 reminders at 1h/12h/24h/48h intervals with escalating urgency. Orders are automatically cancelled after 48h if not paid. Year rollover automatically creates new year settings on Jan 1st. Push notifications are sent when payments are confirmed via PIX webhook (UMP, Percapta, event fees, shop orders). **UMP Full Year Anticipation** (Jan 2026): Members can pay all remaining months (including future) in a single PIX payment via "Antecipar ano completo" button, alongside existing monthly and pending payments options.
- **Event Fee PIX Payment**: Members can pay event fees directly on the event page via `/api/events/:eventId/generate-pix` endpoint. The agenda page (`/agenda`) shows a "Pagar Taxa via PIX" button when a member has confirmed presence and has a pending fee. PIX modal displays QR code, copy-paste code, amount, and expiration. Status refreshes automatically when modal closes to reflect webhook confirmation.
- **Scheduler Persistence**: The `sent_scheduler_reminders` table persists reminder state across server restarts, fixing issues where abandoned cart and loan installment reminders were lost on Render deployments.
- **Study Event Notifications**: Full notification support for study events: (1) Event published - sends to all members, (2) Event starting soon - 24h before start via scheduler, (3) **Event started** - when event begins at 00:00 via scheduler, (4) Event deadline approaching - 24h, 3h, 1h before end via scheduler, (5) Event ended - when admin ends manually or status changes to ended/completed via PATCH. Guards prevent duplicate notifications.
- **Daily Verse System** (Jan 2026): Automated daily Bible verse publishing at 7 AM (America/Sao_Paulo) with AI-generated reflections using Google Gemini. Features include: (1) `daily_verse_stock` table for stock images (nature, contemplative, Christian themes) with rotation based on `lastUsedAt` field, (2) `daily_verse_posts` table for published verses with reflection, image, and active status, (3) Public page at `/versiculo-do-dia` with verse display, reflection, and historical calendar, (4) Social media sharing with html2canvas-generated 9:16 images for WhatsApp/Instagram, (5) Push notifications at 7 AM directing to public page, (6) Scheduler removes verses from banner at 23:59 while preserving in archive, (7) SPA navigation with wouter for historical verse viewing via `/versiculo-do-dia/:date`. APIs: `/api/site/daily-verse` (today), `/api/site/daily-verse/:date` (historical), `/api/site/daily-verses` (history list).
- **E-commerce Shop (Loja)**: Redesigned with Jesuscopy-style design. Features swipeable banner carousel with Embla Carousel and autoplay, category grid with custom images and badges, "Lancamentos" product section. Product pages have swipeable image galleries. Admin panel supports separate banner image upload for home carousel (bannerImageData field in shopItems table). Banner images are independent of product gallery images. Promotional code system with percentage/fixed discounts, category filtering, date ranges, and usage limits. Product delivery at church - no shipping costs. PIX installment payments: products can be configured with `allowInstallments` and `maxInstallments` (up to 12), installments tracked in `shopInstallments` table with due dates (day 10 of each month), push notifications sent 5, 3, 1, and 0 days before due date via `processShopInstallmentReminders` scheduler. **Category Images**: Categories support custom 1:1 images (imageData field) with lazy loading via proxy route `/api/shop/images/category/:id`. When >4 categories, grid becomes horizontal scrollable with snap points. **Manual Orders**: Treasury panel supports creating manual orders for external customers (non-members) with PIX payment generation. Manual orders are flagged with `isManualOrder: true` and customer name extracted from observation field. PIX can be generated for total amount or individual installments via `/api/treasury/shop/orders/:orderId/generate-pix`. PIX buttons only appear for manual orders to avoid conflicts with automated MercadoPago flow. **Stock Inventory Control** (Jan 2026): Products have optional `stockQuantity` field (nullable - null means no stock control). When payment is confirmed, stock is automatically deducted. Items are auto-marked as unavailable (isAvailable=false) when stock reaches 0. **Multiple Image Upload** (Jan 2026): Admin can upload up to 10 images at once per product, maintaining selection order for sortOrder.

### System Design Choices
- **Modular Project Structure**: Clear separation of client, server, and shared code.
- **Database Schema**: Managed with Drizzle ORM.
- **Environment Configuration**: Utilizes environment variables for sensitive data.
- **Root Administrator**: Automatic creation of a root admin user.
- **Deployment**: Optimized for Render, including lazy database initialization.
- **Performance Optimizations**: Extensive use of batch queries (e.g., `LEFT JOIN LATERAL`, `Promise.all`, `inArray()`), caching, and data projection to reduce N+1 queries and improve response times for leaderboards, weekly goals, and lesson progress. HTTP compression (Gzip) is enabled. Database indexes are applied to frequently queried fields. **Shop API Optimization** (Jan 2026): All shop endpoints use lightweight storage functions that exclude Base64 image data. Categories use `getShopCategoriesLight()` + `getShopCategoriesWithImageCheck()` for efficient listing. Admin items use `getShopItemsLight()` + `getShopItemsWithBannerCheck()`. Images are served via proxy routes with Sharp WebP compression (banner: 2000px, items: 2000px, categories: 400px at 80-90% quality) and `Cache-Control: public, max-age=31536000, immutable` headers for browser caching. **In-Memory Image Cache** (Jan 2026): Shop image proxy routes use bounded in-memory cache (200 images max, 24h TTL) to avoid repeated database queries and Sharp processing that caused connection timeouts. **DeoGlory Study Module Optimization** (Jan 2026): Dashboard uses `getWeeksWithLessonsBulkOptimized` for single-query lesson fetching with Map-based lookups; lessons/:lessonId uses Promise.all for parallel queries; final-challenge and crystals routes parallelized; practice-exercises uses batch `getUnitsByLessonIds` method. **Season-Ended Lesson Blocking** (Jan 2026): `getLessonWithSeasonStatus()` uses LEFT JOIN to fetch lesson+season.isEnded in single query; all lesson routes (GET, start, complete-stage, complete) block access when season is ended with proper 404/403 handling. **R2 Image URL Conversion** (Jan 2026): Helper functions `convertImageUrls()` and `convertImageUrlsArray()` in routes.ts systematically convert r2:// URLs to public URLs for all image fields (imageUrl, coverImageUrl, photoUrl, profileImage, bannerImageUrl, bannerImageData) before sending to frontend. Applied to all major APIs: devotionals, events, board members, banners, seasons, study events, collectible cards, and site content.
- **Season End Notifications**: When a season/magazine is ended via admin panel, the system sends push notifications and in-app notifications to ALL participants (not just top 3). Each participant receives personalized notification with their final position and XP. Top 3 also receive congratulatory emails. Uses O(1) position lookup via Map to handle large participant lists efficiently.
- **Admin API Validation**: Strict Zod schemas for all admin UPDATE endpoints to prevent privilege escalation.
- **Error Handling**: Centralized error handling with `AppError` and logger.
